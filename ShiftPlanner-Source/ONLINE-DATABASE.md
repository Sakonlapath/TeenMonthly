# ฐานข้อมูลออนไลน์ Firebase

โปรแกรมใช้ **Firebase Authentication + Realtime Database** สำหรับคลังโค้ดรหัส สมุดบุคลากร และตารางเวรรายเดือน ผู้ใช้กรอก Username กับ Password โดยโปรแกรมแปลง Username เป็นอีเมลภายใน ผู้ใช้ไม่ต้องกรอกอีเมลส่วนตัว ข้อมูลแยกพื้นที่ตามบัญชี

## ตารางเวร ประวัติ และปิดยอดรายเดือน

- เข้าบัญชีเดียวกันเพื่อโหลดตารางจาก `/planners/<uid>/<YYYY-MM>` อัตโนมัติ รอข้อความ **ซิงก์ตารางกับบัญชี … แล้ว** ก่อนย้ายเครื่อง เครื่องใหม่จะเปิดเดือนล่าสุดที่มีข้อมูลให้เมื่อเดือนปัจจุบันว่าง
- เวร OFF/Vac จำนวนคนรายวัน เป้ารายคน การเลือกบุคลากร และข้อมูลหัวเอกสารซิงก์แยกตามเดือน หน้าเดิมตรวจข้อมูลใหม่ทุก 30 วินาทีขณะเปิดใช้งานและไม่มีหน้าต่างแก้ไข กด **โหลดล่าสุด** ได้ทันที
- ออฟไลน์หลังโหลดสำเร็จยังแก้ตารางที่เปิดอยู่ได้ การแก้ไขเก็บในแคชบัญชีและรอส่งเมื่อเชื่อมต่อกลับมา ถ้ายังโหลดครั้งแรกไม่ได้จะหยุดการแก้ไขเพื่อป้องกันทับข้อมูลออนไลน์
- ถ้าสองเครื่องแก้เดือนเดียวกัน ระบบหยุดส่งและให้ **เปรียบเทียบฉบับ** เลือกฉบับในเครื่องหรือออนไลน์ ฉบับที่ไม่ได้เลือกเก็บในประวัติ ต่างเดือนบันทึกแยกกันได้
- ปุ่ม **ประวัติ / กู้คืน** เหนือตารางและหน้าสรุป เก็บฉบับก่อนแก้ไขสูงสุด 20 รุ่นต่อเดือน โดยจำกัดขนาดรวมด้วย แคชเครื่องเก็บ 3 รุ่นล่าสุดหลังส่งสำเร็จ เปิดประวัติเพื่อโหลดรุ่นออนไลน์ กู้คืนแล้วบันทึกเป็นรุ่นใหม่พร้อมเก็บฉบับปัจจุบันก่อนแทนที่
- ตารางเดิมในเครื่องที่ต่างจากออนไลน์จะเก็บเป็นประวัติชื่อ **ตารางเดิมจากเครื่องนี้ก่อนซิงก์** ให้เลือกกู้คืนได้
- **ปิดยอดเดือนนี้** แสดงจำนวนเวรและเงินให้ตรวจ ระบบโหลดเรทบุคลากรล่าสุดก่อนยืนยัน ถ้าเรทเปลี่ยนจะแสดงยอดใหม่ให้ยืนยันอีกครั้ง จากนั้นตรึงตาราง รายชื่อ และเรทของเดือนนั้นไว้ สถานะเริ่ม **รอตรวจ** → **ยืนยันแล้ว** → **รับเงินแล้ว** การยืนยันยอดต้องผ่านการตรวจเงื่อนไขตาราง สถานะรับเงินเป็นบันทึกของผู้ใช้
- เดือนปิดยอดแก้ตารางไม่ได้ การเปลี่ยนเรท/ชื่อในสมุดบุคลากรไม่เปลี่ยนรายงานเดือนปิดยอด กด **เปิดแก้ไข** เพื่อแก้เดือนเดิมโดยยังใช้เรทเดิม หากต้องการเรทใหม่ให้กด **ใช้เรทปัจจุบัน**
- คลังโค้ดรหัสมี **จัดการข้อมูล → ประวัติ / กู้คืนคลังรหัส** เก็บฉบับออนไลน์ก่อนเปลี่ยนสูงสุด 20 รุ่น โดยจำกัดขนาดรวมด้วย กู้คืนแล้วสำรองคลังปัจจุบันก่อนแทนที่
- ประวัติอัตโนมัติใช้เมื่อเข้าสู่ระบบ JSON และ Excel ยังส่งออกได้ตามเดิม ควรดาวน์โหลด JSON เมื่ออยากเก็บรุ่นสำคัญไว้นอกช่วงประวัติ ทั้งสองเครื่องต้องรีเฟรชใช้โปรแกรมรุ่นล่าสุด

## สมุดบุคลากร

- ทุกบัญชีเริ่มด้วยบุคลากรหลัก 8 คน บัญชี `teen` มีปรเมศวร์เป็นคนเพิ่มเติมตามที่เจ้าของกำหนด
- รูป คำนำหน้า ชื่อ ตำแหน่ง และเรทค่าเวร บันทึกใต้ `/personnel/<uid>` เฉพาะเจ้าของบัญชีอ่าน/เขียนได้ เลือก “บันทึกบุคลากร” แล้วรอข้อความ “บันทึกในบัญชี … แล้ว” ก่อนย้ายเครื่อง
- เข้าบัญชีเดียวกันบนเครื่องอื่นจะโหลดรายชื่อให้ เลือก “โหลดล่าสุด” เพื่อรับการแก้ไขระหว่างเปิดหน้าเดิมอยู่ การเลือกลงตารางเดือนนี้และตัวตารางเวรซิงก์ผ่านเอกสารรายเดือน
- เพิ่มคนได้เมื่อเข้าสู่ระบบ รวมรายชื่อและประวัติไม่เกิน 40 คน คนหลักลบไม่ได้ แต่พักจากตารางแต่ละเดือนได้ คนเพิ่มเติมที่ลบจะไม่ลงตารางตั้งแต่เดือนที่เลือก และยังเก็บข้อมูลย้อนหลัง
- รูป JPG/PNG/WebP ไม่เกิน 8 MB จะครอปกลางและย่อเป็น JPEG 192 × 192 ก่อนบันทึกใน Realtime Database ไม่ต้องเปิด Cloud Storage
- ตรวจ revision และ ETag ก่อนส่งข้อมูล ([Firebase conditional requests](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests)) ถ้าอีกเครื่องแก้ไขก่อน จะหยุดส่งและให้โหลดล่าสุด ไม่เขียนทับอัตโนมัติ ข้อมูลที่รอส่งยังอยู่ในแคชบัญชีของเครื่องเดิม
- ออกจากระบบจะคืนรายชื่อในเครื่องและล้างประวัติย้อนกลับของบัญชีออกจากหน่วยความจำ ไฟล์ Excel/CSV รองรับรายชื่อที่เพิ่มเกิน 9 คนโดยขยายแถวตามจำนวนจริง

แต่ละบัญชีมีคลังของตัวเอง บัญชี `teen` เดียวกันบนสองเครื่องเห็นข้อมูลออนไลน์ชุดเดียวกัน บัญชีอื่นเข้าถึงคลังของ `teen` ไม่ได้เมื่อใช้ Rules ด้านล่าง

โปรเจกต์ที่เลือกคือ **teen-program** ตั้งค่า Web API key, projectId และ databaseURL `https://teen-program-default-rtdb.asia-southeast1.firebasedatabase.app` ในโค้ดแล้ว บัญชีภายในของโปรเจกต์นี้คือ `teen@teen-program.firebaseapp.com` สร้างบัญชีและเผยแพร่ Rules แล้ว ตรวจการล็อกอิน/โหลด/รีเฟรช/ออกจากระบบกับ Firebase จริงผ่าน รวมทั้งการบันทึกคลังว่างแบบมีเงื่อนไข การอ่านจากเซสชันที่สอง และการปฏิเสธอ่าน/เขียนโดยผู้ไม่ได้ล็อกอินหรือเส้นทาง UID อื่น การย้าย 12 รหัสเดิมยังต้องนำเข้า JSON สำรอง

## 1. สร้างโปรเจกต์ฟรีและ Web app

1. เปิด [Firebase Console](https://console.firebase.google.com/) สร้างโปรเจกต์ เลือกแพ็กเกจ **Spark** ไม่ต้องเปิดการเรียกเก็บเงิน
2. Project overview → เพิ่มแอป **Web** (ไอคอน `</>`) ตั้งชื่อ เช่น Pruksa ไม่ต้องตั้ง Hosting
3. คัดลอก `firebaseConfig` มาให้ผู้พัฒนา โดยโปรแกรมใช้ `apiKey` และ `projectId`
4. Build → **Realtime Database** → Create database เลือกภูมิภาคใกล้ผู้ใช้ เช่น Singapore หากมีให้เลือก แล้วเริ่มแบบ **Locked mode**
5. คัดลอก URL จากแท็บ Data เป็น `databaseURL` เช่น `https://YOUR-PROJECT-default-rtdb.asia-southeast1.firebasedatabase.app`

เลือก Realtime Database ตามคู่มือนี้ โปรแกรมไม่ได้ใช้ Firestore, Cloud SQL หรือ Cloud Functions ไม่ต้องติดตั้ง Firebase SDK เพิ่ม เพราะโปรแกรมเรียก REST API โดยตรง ทั้งไฟล์แยกและ Standalone ใช้ได้

Spark มีโควตา Realtime Database ปัจจุบัน 1 GB สำหรับจัดเก็บ, ดาวน์โหลด 10 GB ต่อเดือน และเชื่อมต่อพร้อมกัน 100 รายการ ดู [ราคาและโควตา](https://firebase.google.com/pricing) หากถึงโควตาบริการอาจหยุดจนกว่าโควตาจะกลับมา ไม่ได้หมายถึงฟรีไม่จำกัด

## 2. เปิดล็อกอินและสร้างบัญชี teen

1. Build → **Authentication** → Get started
2. Sign-in method → **Email/Password** → เปิด Email/Password แล้ว Save
3. Users → Add user
4. Email ให้กรอก `teen@YOUR-PROJECT-ID.firebaseapp.com` โดยแทน YOUR-PROJECT-ID ด้วย `projectId` จาก config
5. Password ใช้รหัสที่เจ้าของบัญชีกำหนด (อย่างน้อย 6 ตัวอักษร) ไม่บันทึกรหัสผ่านในไฟล์โค้ดหรือ Git
6. เพิ่มผู้ใช้ แล้วนำ **User UID** ไปใช้ตรวจสิทธิ์ใน Rules Playground ได้

อีเมลนี้เป็นตัวระบุภายใน ไม่มีกล่องจดหมายสำหรับรีเซ็ตรหัสผ่าน หากลืมรหัส ผู้พัฒนาต้องจัดการผ่าน Firebase Console ไม่ควรใช้เมนูส่งอีเมลรีเซ็ตกับบัญชีภายในนี้

อ้างอิง [Firebase Auth REST API](https://firebase.google.com/docs/reference/rest/auth)

## 3. ติดตั้งกฎฐานข้อมูล

Realtime Database → **Rules** → วางเนื้อหาทั้งหมดจาก [firebase/database.rules.json](firebase/database.rules.json) แล้วกด **Publish**

หรือใช้ Firebase CLI ที่ล็อกอินบัญชีเจ้าของโปรเจกต์แล้ว จากโฟลเดอร์ repository:

```powershell
firebase.cmd login
firebase.cmd deploy --only database --project teen-program --config ShiftPlanner-Source/firebase.json
```

กฎอนุญาตให้อ่านและเขียนเฉพาะ `/codeLibraries/<UID ของตัวเอง>`, `/personnel/<UID ของตัวเอง>` และเอกสารเดือนใต้ `/planners/<UID ของตัวเอง>` ผู้ที่ไม่ล็อกอินและบัญชีอื่นเข้าไม่ได้ ไม่มีสิทธิ์อ่านรวมทุกบัญชี การล้างคลังบันทึกรายการว่างในคลังตัวเอง ไม่ลบโหนดบัญชี

ตรวจด้วย Rules Playground ก่อนใช้งานจริง:

- ไม่ Authenticate → อ่าน/เขียน `/codeLibraries/UID-teen` ต้องถูกปฏิเสธ
- Authenticate ด้วย UID อื่น → อ่าน/เขียนเส้นทาง UID-teen ต้องถูกปฏิเสธ
- Authenticate ด้วย UID-teen → อ่านเส้นทางตัวเองได้
- การเขียนครั้งแรกต้องมี `version: 1`, `revision: 1`, `recordsJson: "[]"`
- การเขียนครั้งถัดไป revision ต้องเพิ่มทีละ 1 และเขียนข้ามบัญชีไม่ได้

อย่าใช้ Test mode หรือเปลี่ยน Rules เป็นอ่าน/เขียนได้ทุกคนเพื่อแก้ Permission denied อ้างอิง [Realtime Database Security Rules](https://firebase.google.com/docs/database/security)

## 4. เชื่อมโค้ด

ผู้พัฒนาตั้งค่าที่ต้นไฟล์ [js/code-library.js](js/code-library.js):

```js
const defaultConfig=CodeCatalog.config(
  'DATABASE_URL',
  'WEB_API_KEY',
  'PROJECT_ID'
);
```

ค่าเหล่านี้เป็นค่าการเชื่อมต่อสาธารณะ สิทธิ์ข้อมูลอยู่ที่ Authentication และ Rules ไม่ใช้ service account, private key หรือ database secret ใน HTML

หากยังไม่ใส่ค่า โปรแกรมแจ้งว่ายังไม่ได้เชื่อม Firebase โดยไม่พยายามติดต่อเซิร์ฟเวอร์ตัวอย่าง การตั้งค่าไม่อยู่ในหน้าจอผู้ใช้

หลังแก้ค่าให้สร้าง Standalone ใหม่:

```powershell
node ShiftPlanner-Source/scripts/build-standalone.cjs
```

## 5. ย้ายรหัสเดิมจาก Supabase

**ข้อมูลและบัญชี Supabase ไม่ย้ายมา Firebase เอง** ห้ามลบโปรเจกต์เดิมจนกว่าจะตรวจข้อมูลใหม่ครบ

1. จากเครื่องที่ยังเปิดคลังเดิมได้ ให้ดาวน์โหลด **สำรองคลังรหัส JSON** ไว้ก่อนเปลี่ยนไปใช้โปรแกรมรุ่น Firebase
2. เปิดรุ่น Firebase แล้วเข้าสู่ระบบ `teen`
3. จัดการข้อมูล → **นำเข้า / รวม JSON** → เลือกไฟล์ที่สำรอง
4. รอข้อความ **บันทึกออนไลน์แล้ว**
5. เปิดอีกเครื่อง ล็อกอิน `teen` แล้วตรวจว่ารหัสและรายละเอียดครบ

JSON เก่าใช้ได้โดยคงตัวระบุรายการ เงื่อนไข หัตถการ Note และรายการโปรด นำเข้าไฟล์เดิมซ้ำไม่เพิ่มรายการเดิมซ้ำ ถ้าตัวระบุเดียวกันแต่รายละเอียดต่างกัน โปรแกรมให้ตรวจสอบก่อนรวม

คลังที่ไม่ล็อกอินและแคช Supabase เดิมยังอยู่ในเบราว์เซอร์ โปรแกรมไม่ลบหรืออ่านแคชบัญชีเก่ามารวมกับบัญชี Firebase โดยอัตโนมัติ หากไม่มี JSON และเข้า Supabase เดิมไม่ได้ ต้องกู้ข้อมูลเดิมให้ได้ก่อน จึงยังยืนยันการย้ายครบไม่ได้

ไฟล์ `supabase/code-library.sql` เก็บไว้เป็นเอกสารระบบเก่า ไม่ต้องรันสำหรับ Firebase

## การซิงก์และการออกจากระบบ

- เพิ่ม แก้ไข ลบ หรือติดดาวแล้ว โปรแกรมบันทึกในเครื่องก่อนและส่งอัตโนมัติ
- ก่อนส่งโปรแกรมอ่าน revision และ ETag แล้วใช้ conditional PUT (`if-match`) หากมีอีกเครื่องบันทึกก่อนจะหยุดพร้อมเก็บรายการในเครื่อง ไม่เขียนทับคลังใหม่
- ระหว่างส่งยังแก้ไขต่อได้ รายการที่แก้ภายหลังส่งในรอบถัดไป
- ถ้าเน็ตหลุดจะแจ้งข้อมูลรอส่ง และลองส่งเมื่อเชื่อมต่อกลับมา
- ถ้าโหลดครั้งแรกไม่สำเร็จ จะลองใหม่สูงสุด 3 รอบ (รอ 5, 10, 20 วินาที) เมื่อไม่มีรายการรอส่ง และมีปุ่ม **ลองโหลดคลังอีกครั้ง**
- อีกเครื่องที่เปิดค้างอยู่รับรายการล่าสุดโดย **โหลดจากออนไลน์** หรือเข้าสู่ระบบใหม่ รุ่นนี้ยังไม่ได้เปิดตัวฟังข้อมูลแบบเรียลไทม์
- รีเฟรชแท็บเดิมจะใช้ refresh token ใน sessionStorage เพื่อตรวจบัญชีกับ Firebase ใหม่ การเปิดแท็บใหม่หรือเปิดเว็บหลังปิดต้องล็อกอิน
- ออกจากระบบจะพยายามส่งข้อมูลค้างก่อน แล้วล้างเซสชันในแท็บนี้ ไม่ออกจากระบบบนเครื่องอื่น และไม่ได้เพิกถอนโทเคนทุกอุปกรณ์บนเซิร์ฟเวอร์
- แคชบัญชีถูกล็อกผ่านโปรแกรมจนกว่าจะยืนยันบัญชีอีกครั้ง แต่ localStorage ไม่ได้เข้ารหัส ผู้ที่ควบคุมโปรไฟล์เบราว์เซอร์ยังตรวจข้อมูลได้

อ้างอิง [conditional REST writes](https://firebase.google.com/docs/database/rest/save-data) และ [REST authentication](https://firebase.google.com/docs/database/rest/auth)

### ถ้าสองเครื่องแก้พร้อมกัน

สำรอง JSON ในเครื่อง → โหลดข้อมูลออนไลน์ (โปรแกรมสำรองอีกครั้งก่อนแทนที่) → นำเข้า JSON เพื่อรวม → ตรวจรายละเอียดที่ขัดแย้งกัน → รอส่งออนไลน์สำเร็จ

## Excel และการสำรอง

- ส่งออก Excel `.xlsx` ได้ทั้งคลังหรือเฉพาะผลค้นหาทุกหน้า
- JSON ใช้นำกลับมาแก้ไขและย้ายเครื่อง แยกจากไฟล์สำรองตารางเวร
- คลังรองรับไม่เกิน 10,000 รายการ และข้อมูลรายการรวมประมาณ 4.5 MB
- Firebase เก็บรายการเป็น JSON string ใน `recordsJson` กฎจำกัดชนิด/ความยาวและ revision ส่วนโปรแกรมตรวจรายละเอียดแต่ละรายการก่อนอ่านหรือส่ง
- หากพื้นที่เบราว์เซอร์เต็ม ให้ดาวน์โหลด JSON ก่อนปิดหน้า

## แก้ปัญหา

- **ยังไม่ได้เชื่อม Firebase**: ต้องใส่ databaseURL, apiKey, projectId และสร้าง Standalone ใหม่
- **เปิด Email/Password**: เปิด provider ใน Authentication และสร้างบัญชีภายในตามขั้นตอน 2
- **Username หรือ Password ไม่ตรง**: ตรวจอีเมลภายในและรหัสของบัญชี Firebase บัญชี Supabase เก่าใช้แทนกันไม่ได้
- **Firebase ไม่อนุญาต**: ตรวจ Rules และ UID อย่าเปิดฐานข้อมูลเป็นสาธารณะ
- **ข้อมูลออนไลน์เปลี่ยนจากเครื่องอื่น**: สำรอง JSON ก่อนโหลดข้อมูลใหม่และรวม
- **ไม่ตอบภายใน 25 วินาที**: ตรวจสถานะ Firebase/โควตา/เส้นทางเครือข่าย ข้อมูลในเครื่องยังเก็บไว้
- **คลังถูกแก้จากอีกแท็บ**: สำรอง JSON และรีเฟรชก่อนแก้ต่อ

ก่อนส่งให้ผู้ใช้จริง ทดสอบด้วยสองเบราว์เซอร์: ล็อกอิน teen → เพิ่ม/แก้รหัส → รอส่งสำเร็จ → เปิดอีกเบราว์เซอร์ด้วย teen → ตรวจข้อมูล → ออกจากระบบแล้วตรวจว่าเปิดคลังบัญชีไม่ได้ การทดสอบจำลองใน repository ไม่ได้ยืนยันว่า Rules ถูก Publish หรือว่าข้อมูลจริงถูกย้ายครบ
